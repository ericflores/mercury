# 22 — A learned receiver stage (issue #22, research)

**Kind:** research first; if it wins, receiver only, no wire change.
**Depends on:** 00-bench (impairments, replay), 09/19/20 as the baselines it
must beat, 23 (time budget).
**Hardware:** a GPU for training (a GTX 1080 Ti is enough). None for use.

## Goal

Find out, with numbers, whether a network that turns the received
time-frequency grid into soft bits beats the classical chain (09 + 19 + 20,
with 07 and 08 for structured noise) on Mercury's waveforms, in particular
on real recorded noise. Integrate it only if it does.

Read `COMPUTE-AND-NEURAL-RESEARCH.md` section 5 first: what exists in the
literature, and the boundary (a network models the channel and the noise;
it cannot predict payload bits).

A different use of a trained model, outside the data path, is proposal 27:
it names what is degrading the signal and chooses among the receiver's
existing tools. It is much smaller and is judged differently.

## What "winning" means

The yardsticks are already measured (research note 3.2):

| case (DATAC1) | best classical measured | genie ceiling |
|---|---|---|
| white noise, 90 % point | −1.15 dB (09 + 19) | about −2.1 to −2.5 dB |
| CCIR Poor, −0.2 dB | 5 of 54 | 29-33 of 54 |
| disturbed NVIS, +9.8 dB | 15 of 59 | 35-36 of 59 |

On Gaussian noise the network cannot beat the genie. It is worth having only
if it (a) gets closer to the genie than proposal 20 does, or (b) handles
real, structured noise better than 07 + 08, or (c) does the same for much
less engineering. Decide on the bench.

## Data

One sample = one burst:

- `rx`: the received grid, complex, `np·ns + 1` rows × `nc` carriers (pilot
  and data rows as the demodulator produces them **before** any channel
  correction, i.e. `ofdm->rx_sym` rows 1..ns of each frame, plus the pilot
  row after the last frame). With proposal 19, also the recycled rows.
- `pilots`: the known pilot values and a mask of pilot positions; the
  unique-word positions and values.
- `gap`: a noise-only spectrum from the silence before the burst (the
  network's view of interference).
- `bits`: the transmitted coded bits **in grid order** (for each data
  position, its `bps` bits), obtained from the transmitted grid. The lab
  prototype's hook that records the transmitted grid (`mx_txgrid`) shows
  where.
- metadata: mode, channel preset, SNR, offset, seed.

Sources, mixed in every batch:

1. **Synthetic channel:** every Watterson preset (`common/watterson.c`),
   white noise, SNR uniform over the mode's cliff ±4 dB, carrier offset
   ±50 Hz, timing jitter, the synthetic impairments of 00-bench (tones, FSK,
   impulses, inverter presets). Breadth matters more than fidelity to one
   channel (research note, section 5).
2. **Real noise + synthetic burst:** noise-only recordings
   (`MERCURY_RX_DUMP` on a quiet frequency: near inverters idle and loaded,
   power lines, storms, a quiet rural site as the control), with bursts
   generated by the modem, passed through a Watterson preset, added at a
   chosen level. Exact labels, real noise, no second station. Keep whole
   recordings out of the training set for testing.
3. **Real sessions (fine-tuning):** dumps of on-air sessions; frames that
   decoded give their own labels by re-encoding.

Tool: `utils/nn_dataset.c`, built on `rx_bench`, writing one compact binary
file per run (document the layout in its header; little-endian float32).

## Model (a starting point, not a prescription)

- Input: a tensor `[channels, rows, carriers]`: real and imaginary parts of
  `rx`; real and imaginary parts of a least-squares pilot estimate placed at
  pilot positions and zero elsewhere; the pilot mask; the gap spectrum
  broadcast along time; the row's fraction through the burst.
- Body: a residual convolutional network, 6-10 blocks of 3×3 separable
  convolutions with 32-64 channels, dilation growing along time. No
  normalisation that depends on batch statistics. About 0.2-1 M parameters.
- Output: `bps` LLRs per data position.
- Loss: binary cross-entropy per coded bit against `bits`, averaged over
  data positions.
- One model per carrier count is the simple start (3, 9, 27, 33); a single
  model conditioned on the mode comes later if the first works.

Train with any framework that supports the card (for a GTX 1080 Ti: NVIDIA
driver branch 580 and a build against CUDA 12; check the framework's table).
A few hundred thousand bursts and a few hours should show whether there is
a signal.

## Evaluation without integrating anything

1. The trained model writes LLR files for a held-out bench run.
2. A small C tool (`utils/llr_decode.c`) takes LLRs in grid order, applies
   the same unique-word removal and de-interleaving as the modem
   (`ofdm_disassemble_psk_modem_packet_with_text_amps`,
   `gp_deinterleave_*`), runs `ldpc_decode_frame`, the parity gate and the
   CRC, and prints delivered counts.
3. Compare with the classical columns on the **same trials**.

Report: delivery curves per mode on white noise, CCIR Poor, NVIS and
flutter; held-out real-noise recordings against 07 + 08; the false-accept
count on noise-only input; and the model's size and time per burst on one
CPU core.

Also check the failure mode that the literature reports for learned
decoders and receivers: performance on a condition absent from training
(a preset held out entirely, a noise recording from a different site).

## Integration (only on a go decision)

- Export the weights to a C header and run the convolutions in plain C (the
  model is small; no runtime dependency), or behind an optional build flag
  with an inference library.
- One more entry in the fallback attempt list, after the classical
  attempts, under its own switch and the time budget of proposal 23.
- The LDPC decoder, the parity gate and the CRC decide. A wrong network
  costs CPU only.

## What not to try

- A network that outputs payload bytes, "denoised" payload, or anything
  after the decoder. There is nothing there to learn (research note, 3.3,
  3.4 and section 5).
- A learned LDPC decoder for the long codes. Published transformer decoders
  stop near a thousand bits and are fragile off their training noise; the
  control frame is better served by proposal 12.
